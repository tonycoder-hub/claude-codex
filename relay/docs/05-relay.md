# 中继层：会合与可达是两件事，以及为什么要有三个实现

写于 2026-10-22。`04-ingress.md` 决定的是**可达**，这份决定的是**会合**，以及把两者
拼起来的 provider 接口。凡事实按 **已核实 / 推断 / 未核实** 标注。

## 1. 先把两件事分开

- **会合（rendezvous）**：手机侧的客户端和 Mac 上的 adapter 互相不知道对方的地址，
  需要一个双方都能到达的点把两条连接接通。这是 relay。
- **可达（reachability）**：手机在运营商网络里，怎么到达那个点，且 TLS 不终结在
  第三方。这是 ingress，判据是 `04-ingress.md` 的 T1–T4。

混着谈就会得出「某个现成服务能不能当 relay」这种问不清的问题——一个实现作为**会合点**的
协议形状，和它作为**可达手段**的隐私性质，是两套独立的判定。

一句话版本：**relay 决定「谁和谁接上」，ingress 决定「从哪进来」。一个实现要分别
回答这两问。**

## 2. 已经存在的东西，必须先说

**已核实**：Mac 上 `~/.codex-relay/dist/src/` 已经实现了整套中继，并且正在跑——四个
worker adapter 全部以 `--relay ws://127.0.0.1:8790` 在用它。组件：

| 文件 | 它是什么 |
|---|---|
| `relay.mjs` | 中继服务端。依赖面只有 `ws`，刻意如此，「搬动它是一次 `git mv`」 |
| `relay-client.mjs` | adapter 侧。两条规则：够到中继**永远不许拖慢或拖垮启动**；end 的名字只有一个来源 |
| `relay-proxy.mjs` | 把**真 Codex App** 变成一个 end——把 `CODEX_CLI_PATH` 的 stdio 管道指向中继而不是 unix socket |
| `surface.mjs` + `surface-page.mjs` | 一个页面，直接端到端说 app-server 协议，自己从不解析帧 |

`relay-proxy.mjs` 的文件头已经写着我后来独立重新推导出的那句话：

> 这个页面不得不自带一份 UI，是因为浏览器在有人写出客户端之前不是 App Server 的客户端。
> 而 App 本来就是。所以这个文件是同一个想法里更便宜的那一半，而且拿到的是产品自己的 UI。

**所以 codex-relay-web 和它不是重复关系，缺口只有一个。** `surface.mjs` 自己写明了
为什么拒绝绑非回环地址：

> 这个页面把一个活的主会话交给任何能路由到这里的人，而**本进程里没有第二道凭证**
> 能拦住他们。

**那第二道凭证就是 `src/auth/*` 那 68 个测试撑起来的通行密钥门。** 现有中继刻意只绑
回环，不是保守，是因为它没有身份层；补上身份层，非回环绑定才第一次成为可以讨论的事。

还有一条被迫的约束，两边得出了同一个结论：**浏览器的 `new WebSocket()` 不能设置请求
头**，而中继每个 upgrade 都要 header 认证。所以中间必须站一个持 header 的进程——这不是
安全偏好，是协议逼出来的。`surface.mjs` 存在的理由就是这个，而且它由此推出了正确的
下一步：既然非站不可，**它该知道的关于穿过它的东西的量就是零**。

## 3. 线协议（规范）

`src/relay/protocol.mjs` 把它写成了常量与纯函数，下面是人读的版本。认证：每个 HTTP
请求和每个 WebSocket upgrade 都带 `x-relay-token`，用**定时安全比较**。

| 路径 | 谁发起 | 内容 |
|---|---|---|
| `GET /ends` | 任何持令牌者 | `{ends:[{end,connection,pid,host,cwd,runtime,listen,busy,announcedAt,lastSeenAt}]}`，按 end 名升序 |
| `WS /control` | **end** | 上行 `{kind:'announce',end,…}` → 回 `{kind:'announced',end}`；`{kind:'heartbeat'}`。下行 `{kind:'dial-back',pairing,clientEnd}` |
| `WS /attach/<endId>?as=<clientEnd>` | **客户端** | 中继铸 pairing、缓冲早期帧、向 end 发 dial-back，10 s 超时 |
| `WS /pair` + `x-relay-pairing` | **end** 拨回 | 一次性，接通两个 socket，按序重放缓冲 |

接通之后**双向逐字转发，两个方向都不解析**。这份协议盲目性就是重点所在：它让一个
客户端和一个服务端在彼此从未听说过的情况下对话。

四个不显然的决定，每个都有代价明确的理由：

1. **注册寿命 = 控制 socket 寿命，没有任何定时过期。**「一台睡着的笔记本不该看起来
   像一台已经离开的」。心跳只更新 `lastSeenAt` 供人看，不参与生死判定。
2. **attach 按 `(endId, clientEnd)` 这一对键控，不是按 `clientEnd`。** 一个客户端合法地
   要扇出到多个 end；只按名字键控会让它拒绝自己的扇出。而同一个名字两条线接进**同一个**
   end 仍然被拒。
3. **缓冲客户端的早期帧。** 客户端先说话——app-server 握手是一个**请求**，不是问候。
   不缓冲就会丢掉每一条 `initialize`，而且丢得很安静。
4. **pairing 走 header 不走路径。**「路径会进访问日志和错误消息，而这个值不能进」。

`src/relay/` 是对这份协议的独立、零依赖实现（自己握 RFC 6455，复用 `src/surface/ws.mjs`
已有的两半）。目标是**互通**：我们的中继能服务他们的 end，他们的客户端能接我们的中继。

## 4. provider：把「可达」做成可换的

```
start({ target, logger }) -> { kind, publicUrl|null, stop() }
```

两种形状，都得装得下：

- **配置监听者（listener-configuring）**——公网监听者由别的东西产生，provider 只负责
  配置它并报出 URL。Tailscale Serve 和 SNI 透传属于这一类。
- **出站多路复用（outbound-multiplexing）**——provider 自己拨出去，把入向的流解复用成
  一个个 socket 喂给我们的 HTTP 服务器。

第二种之所以能干净地抽象，是因为 Node 允许 `server.emit('connection', socket)` 注入一个
双工流。**于是一个 provider 的职责收敛成一句话：产出 socket。** 这条不是设计偏好，
它是能不能把 ingress 做成可插拔的技术前提。

## 5. 五个实现，分别判定

会合与可达分开判。T1–T4 的定义见 `04-ingress.md` 第 1 节。

| 实现 | 作为会合点 | 作为可达手段 | 判定 |
|---|---|---|---|
| **通用自研中继**（`src/relay/`） | **是**——协议的正本实现 | 不适用，它要别人把它放到可达的地方 | **基础件**，另外两个都站在它上面 |
| **ssh 出站转发** | 复用上一行 | T1 **过**（TLS 终结在我们自己的主机、我们自己的证书）、T4 **过**（`ExitOnForwardFailure` + keepalive 的生产配置本机已在跑）、T3 见下 | **本机今天就能测的那一个** |
| **Tailscale Serve** | 复用 | `04-ingress.md` 判定为推荐 | 按规范实现，**本机从未安装，标注「未在本机验证」** |
| **OpenLark** | 形状不同——不是字节管道，是回合级调度 | 长连接出站，待核实 | 见 `06-im-relay.md` |

### 5.1 ssh 出站转发，以及它为什么是现在最该做的

**已核实**：现有 fleet 的拓扑已经是对的。Mac 上的 `8790` / `8792` 是 `ssh -L` 转发——
也就是说**中继服务端本来就跑在 Mac 之外**，Mac 主动拨出去连它。本机上同时存在多条这样
的长连接，带 `BatchMode`、`ExitOnForwardFailure`、`ServerAliveInterval`，是已经在生产里
跑着的配置。

这一条正面命中那几条约束：TLS 终结在我们自己的主机、用我们自己的证书，不交给
Cloudflare 也不交给 OpenAI（**T1 过**）；不需要安装任何东西（**T4 过**，而且这正是
Tailscale 不行的那个点）；**今天就能测**。

**未核实，而且这是真正剩下的那个未知**：有没有一台我们控制的主机，是**公网上的手机能
直接访问**的。如果候选主机都只在内网，那手机必须先进内网，这完全可用，但那是产品决策
不是技术判定。这份文档不替它假设。

## 6. 对齐协议，不共享代码

`~/.codex-relay/dist/` 是**构建产物**，源码不在本机；它依赖 `ws`，我们零依赖；它的
surface 刻意只绑回环，我们补的恰恰是让非回环成立的那一层。三条加起来，结论是
**在协议上收敛，在代码上各活各的**。

代价是一份协议两个实现会漂移。对冲办法是协议常量与纯解析函数集中在
`src/relay/protocol.mjs` 一个文件里，并且测试主要写在**拒绝**那一侧——重复宣告、扇出
与重复附着、pairing 复用、拨回超时、缓冲重放顺序、二进制保真、令牌拒绝。能漂的是行为，
不该漂的是拒绝条件。
